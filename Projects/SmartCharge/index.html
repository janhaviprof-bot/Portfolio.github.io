Problem Statement

Most EV drivers charge when it is convenient—often during evening peaks—not when the UK electricity grid is cleanest. Carbon intensity varies hour by hour, but that forecast data is not packaged for everyday charging decisions.

Drivers need a simple way to combine 48-hour grid forecasts, their vehicle’s real charging time, and actionable schedules they can put on a calendar. Without that, “green charging” stays abstract rather than operational.

SmartCharge addresses this gap with a data-driven decision-support tool: integrate external data sources, apply constraints, and deliver recommendations users can act on.

What the Application Does

The application allows users to:

  • Describe their EV in plain text (e.g. “Tesla Model 3 Long Range”) and have AI infer make and model, then confirm or edit before specs are loaded.
  • View battery capacity, charge power, and estimated charging time from the EV API, with an LLM fallback when no API match exists.
  • Set a preferred charging duration and receive ranked low-carbon windows for the next 48 hours.
  • See a hero “best slot,” a 48-hour carbon intensity visualization, and all recommended slots labeled low, moderate, or high intensity.
  • Add a recommended slot to Google Calendar or download an .ics file for the suggested window.

All times are shown in UK local time. Carbon data comes from the National Grid ESO Carbon Intensity API.

Technical Architecture

Pattern: Single-page Shiny for Python application with no database; application state held in reactive values in server.py.

  • app.py — Entry point; wires UI and server.
  • ui_components.py — Layout, dashboard cards, intensity strip, custom CSS.
  • server.py — Vehicle lookup, confirm flow, slots pipeline, calendar modal.
  • utils.py — All REST and LLM integrations, date/ISO8601 helpers, charging-time logic.

Data flow: User input → Ollama make/model parse → EV specs (API Ninjas or LLM fallback) → 48h intensity fetch (pandas) → effective_hours = max(slot_length, vehicle_charging_time) → OpenAI slot ranking → UI update and calendar export.

External services: UK Carbon Intensity API, API Ninjas EV API, OpenAI Chat Completions (gpt-4o-mini), Ollama Cloud.

Deployment: Docker image and publish to Posit Connect (rsconnect-python).

Results & Metrics

Systems engineering demonstration

Integrates, processes, and utilizes API-based live data streams alongside LLM-driven intelligent analysis to support informed, data-driven operational decision making in dynamic systems environments.

  • Problem framing — translates an abstract sustainability goal into operational charging decisions with clear inputs and outputs.
  • API-based data — ingests live REST responses (UK National Grid carbon intensity, EV specification APIs), normalizes forecasts and vehicle parameters, and combines them in one reactive pipeline.
  • Informed decisions — ranks charging windows from that combined data so users choose forecast-backed low-carbon slots instead of convenience-only timing.
  • AI when APIs fall short — uses LLM parsing and spec fallback when vehicle lookup or API coverage is incomplete, keeping the decision path usable end to end.
  • Verification — live Posit Connect deployment lets reviewers exercise the full path from vehicle lookup to calendar export without local setup.
