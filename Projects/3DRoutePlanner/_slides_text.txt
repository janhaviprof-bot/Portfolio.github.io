SECTION B — FRAMEWORK 1 Dijkstra I - Concept IMPLEMENTATION Input nodes, edges from  build_visibility_graph () Adjacency list Each edge → both ends; weight = ‖p1 − p2‖ Priority queue 	 (distance, node) — pop minimum Relax  Update neighbor if shorter path found Reconstruct  Backtrack from goal to start COMPARATIVE FRAMEWORKS FOR 3D URBAN PATH PLANNING  |  CAPSTONE PRESENTATION Problem: On the visibility graph, find the minimum total distance from start to goal. Edge cost: Euclidean 3D length of each visible segment (non-negative). Method: Greedy expansion from start; always process the closest unvisited node next (min-heap). Guarantee: Shortest path when all weights ≥ 0 (true for distances). SECTION C — FRAMEWORK 2 No Fly Zone Creation IMPLEMENTATION Input Read 3d_structure (text grid) Clean Replace  NoData  /  NaN  / inf with 0 Buffer Buildings Max-filter H over horizontal-buffer footprint → local max building height Formula B[ i,j ]=max( ground_clearance,max  ( H[k]+ rooftop_clearance )) COMPARATIVE FRAMEWORKS FOR 3D URBAN PATH PLANNING  |  CAPSTONE PRESENTATION OUTPUT B : 3d_structure_nfz10.csv  (min safe altitude m/cell)  H : 3d_structure_height.csv (original) Concept ✓  Approximation assumptions  Uniform  horizontal_buffer_m  (sideways buffer),  rooftop_clearance_m ,  ground_clearance_m  (three parameters, not cuboid ±X/Y/+Z). Buffer built from raster cells, not  gridtoBlock  cuboids. Horizontal reach uses  cell_size_m  and a conservative cell-intersection footprint. Building cells: H > 0; ground cells contribute only via ground clearance unless inside building buffer. Overlap in dense areas is implicit (max over neighborhood — conservative). Static 2.5D field only; no curved corridors or dynamic rules. After building-height grid H is available (3d_structure or  GeoTIFF ), compute forbidden/low-safe flight altitudes as matrix B per cell. Building influence: horizontal buffer around each positive-height cell; fly at least rooftop clearance above the tallest nearby building height. Ground influence: cells not affected by buffered buildings get minimum altitude ground clearance (low-altitude NFZ analogue). Representation: one scalar B[ i,j ] per raster cell (2.5D field), not axis-aligned 3D NFZ boxes.

SECTION C — FRAMEWORK 2 A* - Concept IMPLEMENTATION Input H CSV (building heights), B CSV (min safe altitude / NFZ ceiling) Feasibility Fly only if z ≥ B[row, col]; optional conservative  edge_check Priority queue 	 (f, counter, node) with f = g + h — pop minimum f Relax  Update neighbor if shorter g found; push with new f Reconstruct  Backtrack from goal to start COMPARATIVE FRAMEWORKS FOR 3D URBAN PATH PLANNING  |  CAPSTONE PRESENTATION Problem: On a 3D cell graph, find minimum 3D path length from start to goal while staying at or above the buffer altitude field B. Edge cost: Euclidean 3D distance between neighboring states (26-connectivity by default); all costs ≥ 0. Method: Best-first search — always expand the node with smallest f = g + h (min-heap); g = cost from start, h = straight-line 3D distance to goal. Guarantee: Optimal on this discretized graph when h is admissible (underestimates true cost); straight-line 3D h satisfies this. OUTPUT path_pair_XXXX.csv — waypoint list (row, col,  altitude_m ) + route_summary.csv metrics  OD only where H = 0; start/goal at B; on ground NFZ floor → vertical-only moves (like Dijkstra lift); no horizontal travel at clearance floor Prechecks

SECTION E — CONCLUSION Conclusion For dense cities like Hong Kong,  Framework 1 (VG + Dijkstra)  is the more practical choice for city-scale UAM routing — lower compute per route, sparse graph, reusable NFZ geometry. Framework 2 (buffer + A)*  is better when minimum distance matters and heavy offline compute is acceptable (local corridors, pre-flight optimization). --- Slide 35 ---
SECTION E — CONCLUSION Recommendation for Hong Kong Primary recommendation Use Framework 1 (VG + Dijkstra) as the main pipeline for Hong Kong-style dense cities City scale: Hong Kong’s built-up area implies millions of raster cells — full-grid A* does not scale for real-time or large batch OD sets (demo already: up to ~147 s / 1.8 M expansions on 720×720). Operational fit: After one-time cuboid + NFZ build, each route uses very few graph nodes — suitable for dispatch, replanning, and multi-vertiport networks. Acceptable trade-off: Paths are ~8–20% longer than buffer A* in our tests, but predictable and much cheaper to compute. Limitations: F1: cuboids over-approximate buildings → conservative, longer routes. VS When Framework 2 still makes sense COMPARATIVE FRAMEWORKS FOR 3D URBAN PATH PLANNING  |  CAPSTONE PRESENTATION Offline mission planning in a local corridor (vertiport ↔ vertiport) Fuel / range critical flights where minimum distance justifies compute GIS raster workflow (DSM/TIF) with coarser grid or hierarchical A* (future work) Limitations: F2: 2.5D buffer, grid steps — accurate locally but too heavy city-wide without acceleration Hong Kong UAM routing: prefer VG + Dijkstra for city-scale operations; reserve buffer + A when high-fidelity, compute-rich local optimization is required.
